Local Asset-Path Robustness
- Root cause identified: output/index.html referenced the Showcase asset bundle via "../assets/Reconnecting_Dunhuang_Showcase_Assets_FINAL/...", which assumed a sibling assets/ folder one level above output/. When output/index.html is opened directly (double-clicked, no local server), some environments do not resolve that parent-relative path correctly, causing historical images, diagrams, and icons to fail to load and CSS background-image sections to render without their photograph. This was a path-resolution issue only; the image files themselves were never corrupted or replaced.
- Fix: copied the approved Showcase asset bundle into output/assets/Reconnecting_Dunhuang_Showcase_Assets_FINAL/ (byte-for-byte identical, SHA-256 verified against the original) and rewrote every reference in output/index.html from "../assets/Reconnecting_Dunhuang_Showcase_Assets_FINAL/..." to "assets/Reconnecting_Dunhuang_Showcase_Assets_FINAL/...". This covers all <img src="..."> references and all CSS background-image url(...) references (historical images, diagrams, icons), plus one unused CSS custom property that also held a stale "../assets/" value.
- Removed the now-duplicate top-level assets/ folder; the asset bundle now lives only under output/assets/, so the output/ folder is fully self-contained.
- No image files were replaced or altered. The Hero photograph remains hero_cave16_manuscripts.jpg, the Pelliot photograph remains history_pelliot_cave17.jpg, and the donor portrait remains context_donor_portrait_cave17.jpg. No visual composition or design was changed.
- Verified by directly loading output/index.html via the file:// protocol in a headless browser (no local server): 0 remaining "../assets/" references in index.html; 0 missing local visual resources; 0 failed local file:// requests; all 37 <img> elements resolve except one intentional empty-src lightbox placeholder that only receives a src on click; all required images (Hero, Pelliot, donor portrait, Wang Yuanlu, manuscript, all three diagrams, all seven icons, both model SVGs) independently confirmed to load with nonzero natural dimensions; all four CSS background-image sections (Hero and three others) independently confirmed to render the correct photograph.
